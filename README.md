# AI-ассистент для генерации карточек товаров

Веб-приложение на **Streamlit**, которое генерирует черновик карточки товара для B2B-интернет-магазина контрольно-измерительных приборов. Пользователь вводит название, производителя, характеристики и описание прибора, а локальная языковая модель через **Ollama** формирует готовый Markdown-текст карточки.

Проект решает задачу автоматизации рутинной работы контент-менеджера: вместо ручного написания SEO-заголовка, описания, списка характеристик и коммерческого блока достаточно передать исходные данные о товаре.

## Возможности

- Удобная веб-форма для ввода данных о товаре.
- Валидация обязательных полей с понятными сообщениями об ошибках.
- Разбор характеристик из текста формата `Параметр = Значение` (по одной строке на параметр).
- Генерация карточки строго по заданному шаблону:
  - SEO-заголовок (до 70 символов, с названием и производителем);
  - SEO-описание;
  - структурированный список ключевых характеристик;
  - поисковые запросы (3–5 ключевых фраз);
  - commercial-блок для менеджера (кому подходит прибор и какие задачи решает).
- Защита от галлюцинаций на уровне промпта: модели запрещено придумывать характеристики, разрешено использовать только переданные данные.
- Локальная работа модели — данные не отправляются во внешние сервисы.
- Автоматические тесты и CI через GitHub Actions.

## Установка

### 1. Клонирование репозитория

```bash
git clone <URL-репозитория>
cd testTask_AIdev
```

### 2. Виртуальное окружение и зависимости

Windows (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Установка и запуск Ollama

Установите [Ollama](https://ollama.com/download) и загрузите модель, указанную в приложении:

```bash
ollama pull qwen2.5:3b-instruct
ollama serve
```

По умолчанию Ollama доступна по адресу `http://localhost:11434`, клиент `ollama` использует его автоматически.

## Запуск приложения

```bash
streamlit run main.py
```

После запуска Streamlit откроет интерфейс в браузере (обычно `http://localhost:8501`).

## Как пользоваться

1. Заполните поля формы:
   - **Название товара** — например, `Манометр показывающий DM 02`;
   - **Производитель** — например, `Манотомь`;
   - **Характеристики товара** — по одному параметру на строку в формате `Параметр = Значение`;
   - **Описание / Фрагмент тех. паспорта** — назначение и особенности прибора.
2. Нажмите **«Сгенерировать карточку товара»**.
3. Дождитесь окончания генерации — результат отобразится в интерфейсе в виде Markdown-текста, готового к копированию.

Пример заполнения поля характеристик:

```
диапазон измерений = 0–1,6 МПа
класс точности = 1,5
присоединение = G1/2
диаметр корпуса = 100 мм
```

Если хотя бы одно обязательное поле пустое, приложение покажет ошибку и не станет обращаться к модели.

## Как это работает

1. `main.py` принимает данные формы и проверяет обязательные поля (`validate_input`).
2. Строки характеристик разбираются по первому символу `=` и собираются в словарь `specs`.
3. Данные сериализуются в JSON и вместе с системным промптом передаются в `generate_product_card` (`llm_processing.py`).
4. Запрос выполняется через `ollama.chat` с параметрами `temperature=0.2` и `max_tokens=2000` — низкая температура снижает вариативность и помогает соблюдать структуру.
5. Ответ модели возвращается в интерфейс и выводится через `st.markdown`.

Системный промпт задаёт роль технического копирайтера, запрещает выдумывать характеристики и фиксирует обязательную структуру ответа. Если при обращении к Ollama возникает ошибка, функция возвращает текст с её описанием вместо карточки.

## Примеры работы

Ниже приведены реальные результаты генерации по примерам из папки `items/`. Полные версии сохранены в `results/output1.md` и `results/output2.md`.

### Пример 1 — `items/product1.json`

Входные данные:

```json
{
    "name": "Манометр показывающий DM 02",
    "manufacturer": "Манотомь",
    "specs": {
        "диапазон измерений": "0–1,6 МПа",
        "класс точности": "1,5",
        "присоединение": "G1/2",
        "диаметр корпуса": "100 мм"
    },
    "description": "Прибор предназначен для измерения избыточного давления..."
}
```

Сгенерированный ответ (`results/output1.md`):

```markdown
# SEO-заголовок
Манометр показывающий DM 02 от Манотомь

# SEO-описание
Манометр показывающий DM 02 от Манотомь – высокоточное измерительное устройство, предназначенное для измерения избыточного давления. Обладая широким диапазоном измерений от 0 до 1,6 МПа и классом точности 1,5, он обеспечивает точные результаты в различных отраслях промышленности. Присоединение G1/2 и диаметр корпуса 100 мм делают его универсальным и удобным в использовании.

# Структурированный список ключевых характеристик
- Диапазон измерений: 0–1,6 МПа
- Класс точности: 1,5
- Присоединение: G1/2
- Диаметр корпуса: 100 мм

# Поисковые запросы
- манометр показывающий Манотомь
- измерительные приборы Манотомь
- избыточное давление измерение
- промышленные манометры
- измерительные приборы для газа

# Commercial-блок для менеджера
**Кому подходит прибор:**
- Менеджеры по снабжению и закупкам
- Эксплуатационные службы промышленных предприятий
- Специалисты по эксплуатации оборудования

**Какие основные задачи решает:**
- Точное измерение избыточного давления
- Управление безопасностью на производстве
- Оптимизация расходов на обслуживание оборудования
```

## Тестирование

Запуск тестов локально:

```bash
pytest -v
```

Покрытые сценарии (`tests/test_validation.py`):

- успешная валидация полностью заполненных данных;
- обнаружение пустых обязательных полей;
- корректный разбор характеристик из строк вида `Параметр = Значение`.

Тесты запускаются автоматически в GitHub Actions (`.github/workflows/tests.yaml`) при push и pull request в ветки `main`/`master` на Python 3.11.

## Ограничения и особенности

- Качество и структура ответа зависят от локальной модели. `qwen2.5:3b-instruct` — компактная модель, поэтому формат вывода может незначительно отличаться от шаблона (например, уровни заголовков или фактическая длина SEO-описания).
- Приложение не сохраняет результат в файл: готовый Markdown-текст выводится в интерфейсе и копируется вручную.
- Файлы из `items/` — это примеры данных, а не автоматически загружаемый набор. Данные вводятся через форму.
- Строки характеристик без символа `=` игнорируются при разборе.
- Для работы генерации Ollama должна быть запущена, а модель — загружена локально.
- Для генерации используется модель `qwen2.5:3b-instruct`, заданная в `main.py`; при необходимости её можно заменить в вызове `generate_product_card`.
